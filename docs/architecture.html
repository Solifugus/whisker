How a whisker program reaches a screen

One program, written in any language that can call C, draws through the same few layers whether its screen is a desktop window, an RV-9 panel, a browser, or a client on another machine. This page shows those layers, where the remote design (D25, §5al) fits, and what each language has to provide.

Is /w0 the client for RV-9?

No, /w0 is RV-9's screen: the device a program writes SVG to and RV-9's rasteriser draws. It does the same job on a board that the SDL window does on a desktop. In fact the desktop window is RV-9's /w0 driver, compiled for Linux.

A client on RV-9 would be a small module that receives a remote program's documents over the network and writes them into /w0, and reads /touch and sends the points back. /w0 is where it draws, not the client itself. RV-9 can also be the other end: a module serving its own window to a desktop or a phone, which is design §9.6, "an X11 for appliances".

The layers every program sits on

From the top: a program, the language's way of describing a window, whisker itself, the host contract, and a host that owns the actual screen. Only the host differs between a desktop, a board and the network.

One program, a local window or a remote screen

The same binary decides at start. If WHISKER_DISPLAY names a client or desktop, it shows there. If there is a graphical session, it opens its own window. If it is headless, it serves and prints where to connect. Remote traffic goes over SSH first, with SSH as the lock and the tunnel, and the program, not the operating system, deciding who each person is.

What each language provides

whisker is C with no dependencies, so any language that can call C can use it. What a language has to supply is a way to describe a window that fits its own style, mapped onto whisker's trees.

Who owns what

The same rule runs through RV-9, gBASIC's G-SQL and whisker: the application owns its people and their rights; the layers below carry them and decide nothing.

The program

All state, its users, their permissions, and what each seat may see. A login screen, or keys kept in its own tables.

whisker

Nothing between calls (D5). It turns a tree into SVG and an event into what changed, and defines no users or roles.

The host

The screen, the input, window and seat numbers, and at most "this connection came with key X", passed on and never interpreted.

SSH

Encryption, and whether a connection may reach the program at all. Never the user directory: no one needs an operating-system account.
